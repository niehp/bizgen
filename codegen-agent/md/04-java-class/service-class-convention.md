# Service クラス設計規約（クラス級）

## 目的

ユースケース 1 つに対して Service クラスを 1 つ作る。画面やバッチの都合でクラスを増やさない。

## 構成

- フィールドは依存対象のみを持つ。定数は `private static final` にする。
- コンストラクタインジェクションを基本とし、生成側で `new` を増やさない。
- 公開メソッドはユースケース md に書かれたものだけ。以前の類似コードにあった別機能は持ち込まない。

## コメント

クラス Javadoc には「何を担当するクラスか」と「なぜこの層に置くか」を日本語で 2 文以内で書く。

例:

```java
/**
 * 受注検索ユースケースを実現する。
 * 検索条件の検証とリポジトリ呼び出しをこの層に閉じ、画面側から API の詳細を隠す。
 */
```
